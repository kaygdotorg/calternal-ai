| R1 | Durable waits ("parking") on a signal or a deadline | PI README "Signals" (:214): a task sleeps on a typed key and holds no process; delivery answers `delivered / duplicate / invalid / closed / not_found`; early signals are kept; one wait per key. "Tools that park" (:392): a tool returns `{ sleep: { signals, until, checkpoint } }` and is re-run on wake. | A plugin operation can wait days for a webhook, a CI result or a person without a live worker. | R2 | Approval gates that park before an operation runs | PI README "Gates before a tool runs" (:783): `beforeTool` returns `{ sleep }`; every wake re-runs all gates; "an approval binds to the arguments it saw; a later hook that rewrites them can run the call with arguments nobody approved". | "Ask a manager before this cal sends mail" as a plugin, not a host feature.
