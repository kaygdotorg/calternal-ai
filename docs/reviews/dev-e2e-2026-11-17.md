## Remaining qualification

- The merged Threads adapter reads a flat chunk. Dev-01 sends the provider
  event at `chunk.data.event`. The runbook has an exact event example for the
  UI lane.
- Browser first-owner passkey setup requires a clean installation and ceremony UI.
  The conformance suite exercises the first-owner flow with a software authenticator.
- The coordinator owns Caddy. The browser installation is ready for setup and
  still needs its own passkey account, space and machine. The seeded server
  used the earlier build for the real turn and remains separate.
- A second saved-thread send starts a fresh provider session. Reusing the
  prior job checkpoint would cover a near-term same-account follow-up with
  a small diff, but final jobs are pruned after seven days or above 1,024
  per space. The durable option needs an account-, provider- and machine-bound
  continuation record whose lifecycle follows the thread. It also needs a
  decision on visible transcript handoff when the provider or machine changes.
  A shared thread can have multiple senders, each with their own sandbox home.
  The lane left continuation unchanged.
- The reset command retains provider homes and was reviewed without erasing the
  active test installation.

## Simplification opportunities

- A supported private listen address in the server would remove the lane's TCP
  relay and keep listener checks in the server lifecycle.
- A shared example of the provider job SSE envelope could drive both the browser
  adapter test and the deployment proof.
