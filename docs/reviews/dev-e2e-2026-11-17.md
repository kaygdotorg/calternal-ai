reported `extension timed out` after 3.008 seconds. In the instrumented

container death, 14 Podman starts exited 126 in 301–1,912 ms with `crun`

worker still draining, and failed after 19.97 seconds.

The separate resource-limit probe reproduced `join keyctl` during sandbox

limits, ordered stdin or the 10-second kernel counter deadlines. The failed

three seconds each. The optional Podman plugin-host run ended with 2 passed
and 16 failed in 64.30 seconds, with unavailable workers and execution

### Leak paths and fixes

- The coordinator found 172 leftover thread containers and restored startup
  by removing 122 old disposable containers, lowering the account from 200
  to 39 kernel keys. The Podman release path used `stop`, which kept the
  container and its overlay. It now removes the exact runtime container
  while preserving the bind-mounted workspace and provider home. Failed starts
  use the new container ID for cleanup. The machine lock scopes the startup
  sweep to ownership labels and recognized workspace mounts in its own root.
- The machine joins in-flight starts on clean exit and revocation. Server
  shutdown fences active leases and asks connected machines to release them.
  A machine that loses contact removes local containers when it observes its
  lease TTL has elapsed. The same TTL bounds idle provider containers on a
  connected machine, with a check at the next successful poll. A retry wait
  retains its logical lease and can start another container on the same machine.
- The plugin worker pool now retires and drains workers while its runtime is
  still available. It retries failed cleanup with the physical permit held.
  Worker idle retirement keeps the existing 60-second limit.
- Machine, server and conformance fixtures remove their own containers on
  unwind, after stopping any child machine. The shell gate assigns a private
  `TMPDIR` and refuses containers labelled with roots in that run. A deliberate
  leak made the gate fail. The scoped test container was then removed.

Each machine admits at most `--max-sandboxes` assigned slots, 10 by default
and 2 in this lane. This includes provider and worker slots, starts, and live
containers whose removal has yet to be confirmed. Idle provider leases keep
their logical slots, so parking cannot increase the physical limit. Mounted
workspaces and provider homes follow the existing retention policy.

## Simplification opportunities

- A supported private listen address in the server would remove the lane's TCP
  relay and keep listener checks in the server lifecycle.
- A shared example of the provider job SSE envelope could drive both the browser
  adapter test and the deployment proof.
- A reproducible VM staging command that removes deleted tracked files would
  eliminate the manual cleanup after a plugin directory is renamed.
- Use the same scoped Podman check in the developer test runner and CI so
  callers need fewer test-specific commands.
