## Delivery

The account's pending list and feed cover an agent's GenUI question, an
approval, and the existing secret prompt. The job stream publishes waiting
state without the private request. Approvals use a live installation session
and fresh passkey proof. Answers and denials use the signed-in recipient.
Every space entry rechecks current capability. Secret input retains its
separate trusted provide endpoint and fifteen-minute lifetime.

Requests and final decisions use protected authority rows. This-thread grants
survive later runs and are erased on archive or delete. A once grant uses a
conditional protected claim bound to one action request ID and fingerprint.
Native writes with durable operation receipts and reads use this path.
Questions and approvals park as waiting jobs and release the lease before
acknowledgement. Startup recovers a parked turn whose decision already committed.
The recorded machine is mandatory during placement after a
decision. A space's Owner or Managers can read or replace `AI/AGENTS.md`
through one journaled operation.

## Unfinished work and questions

- Once consumption fences reuse in the protected transaction. It does not
  rotate the live token at consumption time. Approval and thread lifecycle
  changes still rotate or revoke credentials. A same-machine restart reuses
  credential bootstrap but interrupts the calling tool and needs scoped
  receipt replay. A protected local credential file or socket lets the
  process continue and changes provider and CLI integration.
- Once approvals for unreceipted writes are refused. Underlying operation
  adapters can publish a recoverable intent and receipt. Outside services can
  provide result lookup and durable idempotency keys, with per-service
  reconciliation and failure semantics. Plugin host calls also retain their
  independent kind scope. A cross-kind invocation needs a bounded way to carry
  its approved action into those checks.
- The durable request rows and the account-feed bookmark live in different
  stores. A crash before publishing an invalidation can require an
  authoritative inbox refresh. Secret expiry is enforced by listing and
  providing, and prompts give clients the expiry time. A source-store feed
  outbox would retain precise invalidations across crashes. Account snapshots
  on reconnect would add fewer writes and could delay an already open stream.
- The same-thread provider resume processes the bounded resolved request
  context. Questions remain private in server responses. A provider can still
  choose to discuss a person's answer in a shared conversation.

## UI handoff

The upstream web request adapter still uses its provisional wire shapes.
The shipped backend contract lists across the whole account with
`requests.list {}`; the result tags variants with `detail.kind`. Questions
use `requests.answer {id, answer}`, and a thread approval uses
`requests.approve {id, lifetime: "this_thread"}`. Secret values go through
`POST /api/v1/auth/secrets/provide` using the existing session freshness check.
The existing `secrets.revoke` operation can cancel a secret prompt.
The adapter can follow `/api/v1/account/live` with the existing bookmark and
reload the list on invalidation. The UI lane owns those adapter updates.

  metadata so the native writer eligibility list can disappear.
