The controller used the following switch sequence with the same disposable
installation and authentication session:

1. `deploy/deploy.sh --target deploy/.env.rehearsal --image rehearsal-a --initialize`
   paired the roots. The first activation rolled back because the Quadlet
   override failed the shell-free health check. With the override removed, the
   unit inherited the working image probe and the next activation served first
   owner setup from those roots.
2. `deploy/deploy.sh --target deploy/.env.rehearsal --image rehearsal-b` promoted
   a different image ID. `nix develop -c node deploy/rehearse.mjs verify` with
   the same origin, roots and machine URL found the same owner session,
   completed job and saved Markdown.
3. `deploy/deploy.sh --target deploy/.env.rehearsal --image rehearsal-bad`
   returned exit 1 for a candidate with a deliberately failing probe.
   The prior image ID returned to `:current`, and the verification phase
   recovered the same session, job and Markdown.
4. `deploy/rollback.sh --target deploy/.env.rehearsal --dry-run` printed the
   SSH command. Running the same command without the flag switched the image
   ID back. The `restart` phase of the probe examined a live sandbox's
   1 CPU, 1 GiB and 256-PID limits and checked its mounts. Scoped service
   restart interrupted the active turn. Explicit Resume completed it with the
   same provider session. Podman returned no containers with this installation's
   sandbox-root label afterward.
5. `deploy/deploy.sh --target deploy/.env.rehearsal-real --image rehearsal-real`
   switched the enrolled machine to official Claude Code. The coordinator
   confirmed that the real-provider turn completed, the server was healthy and
   both services stayed active. The rehearsal instance remains running.
6. `deploy/deploy.sh --target deploy/.env.rehearsal-init --image first --initialize`
   verified the final units on fresh, disposable roots and port 34448. The setup
   status was ready, the token file had mode 0600 and the deploy output gave only
   its path. The temporary proof instance was removed.

The rehearsal TLS edge was a disposable reverse proxy with Traefik's relevant

## Decisions and handoff

- The cutover stops the old container's calternaldav service on port 993.
  The owner's phone and Mac will lose contacts, reminders and calendar sync
  until the bridge is available. The old container and data provide the
  cutover rollback.
- The runbook records options and costs for schema transitions, existing-data
  import and coordinated backups. Confirm the HDD backup, the production
  architecture and the proxy's transport address during cutover.
- The machine-enrollment UI remains separate work. The owner signs up with a
  passkey and the operator can enroll the machine through the CLI on day one.

## Simplification opportunities

- Let the shared machine status report the configured provider image and
  effective sandbox resource limits. The operator can then verify the deployed
  shape with one command.
- Switch the worker runtime image from a tag to a build-record digest once
  the release inventory covers both sandbox image families.
