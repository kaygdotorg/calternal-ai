2026-11-18 · [Lane #50](https://git.kayg.org/kayg/calternal-ai/issues/50)

## Part A

The CLI scaffolds a TypeScript package from the same manifest template used by
the guide. The generated manifest types bind handler inputs and outputs. The
SDK supplies a bounded worker transport and a fixture host. Worker frames
are decoded once. Independent calls can be submitted together, with one wire
request and authorization check per call. The package's README and the Rust
manifest schema are checked by the author commands.

The operator can review, pack, install, update and remove packages without
building a new server image. Activation of a catalog change is at server
startup. The operator approves the exact checksum. A change in requested
authority also requires a space manager to enable that package in the space.
The catalog persists a bounded copy of the approved package and seeds shipped
packages on the first start. Workers use the same per-space broker and sandbox
for installed packages. Native Notes and Threads still have host bindings.

The guide explains, scaffolds and checks a manifest and can publish its
reference and walkthrough as a Markdown item in the current space. Its
packaged skill follows the Agent Skills layout. Installed-skill discovery
remains separate.

## Live install and reload follow-up

The running server applies operator-approved catalog changes through its
private, same-user socket. Readers retain one immutable catalog snapshot per
operation. Candidate code starts in a fresh sandbox and receives a bounded
challenge before publication. The challenge has no user, space or broker data.
The SDK checks that every operation has a handler before replying.

A widening update requires new space approval while old work keeps its
narrower grant. Narrowing or removal fences the old revision at the broker
and discards late delivery. The package store retains authorized immutable
archives for durable jobs. Drafts use an explicit development build and
development mode. They are scoped to one space and disappear at restart.
A normal build rejects the draft transport action and omits the command.

The scaffold watch path uses esbuild and manifest validation. The fixture
test path also runs the TypeScript type checker. Author commands report
separate build and activation timings. JSON output in watch mode is one
record per attempt. A rejected build leaves the previous revision available.

## Plugin-owned slots

ID. The declaration sets a space capability, the accepted operation-backed
renderers and a capacity of 1 to 32 visible contributions. A contributor's
operation supplies its capability check. `plugins.list` returns only mounts
and contributions that resolve for that caller. It reflects disable and
removal on the next request. The scoped reactive values contract will push
the same projection to the slot owner. The UI lanes own placement and
rendering, including the opaque-card rule for any sealed frame.

## Review of the remaining warm worker hops

The browser, runner link and worker pipe are separate trust and process
boundaries. Keep browser ingress and delivery, the sync hand-off, both
worker pipe directions, result validation, and the broker's live checks
at the effect and disclosure boundaries. The single read operation needs
one round trip to the broker. Its reply supplies the data the worker uses
to calculate the view. The measured trace groups server work with relay
and delivery costs, so it cannot assign the whole group to SQLite.

One successful completion with one host read calls the worker broker's
authorization seven times. Invocation creation and outbound dequeue each
check once. The callback checks before the effect, after the effect and
again on outbound dequeue. Completion receipt and delivery dequeue each
check once. Each successful broker authorization reads live capabilities
from the authority database and the activation generation from the
space's content database. It also checks the current in-memory registry.
A real browser installation incurs an additional indexed installation
list lookup at each broker check. The benchmark's disposable bearer
uses the static worker session, so it skips that installation lookup.

HTTP dispatch reads activation before invoking the worker. On return it
reads activation again, independently checks current space grants, checks
the session, and validates the generated view. The HTTP guard then checks
the original credential on response delivery. Its credential path can use
the session cache. The development bearer fallback reads whether the
account remains active. The activation reread is a real database read,
and it is separate from the broker's seven reads. These reads do not add
flushes to a read-only operation.

| Candidate | What preserves the checks |
| --- | --- |
| Remove duplicate checks on adjacent worker-session steps | For a read-only reply, combine receive and dequeue in the server adapter or move the check to the disclosure edge. Keep the pre-effect check and check after any enqueue that can yield. For completion, retain schema validation and one fresh check at delivery.
