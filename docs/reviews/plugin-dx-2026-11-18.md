# Plugin authoring and interface checkpoint

2026-11-18 · [Lane #50](https://git.kayg.org/kayg/calternal-ai/issues/50)

## Part A

The CLI scaffolds a TypeScript package from the same manifest template used by
the guide. The generated manifest types bind handler inputs and outputs. The
SDK supplies a bounded worker transport and a fixture host. Worker frames
are decoded once. Independent calls can be submitted together, with one wire
request and authorization check per call. The package's README and the Rust
manifest schema are checked by the author commands.

The operator can review, pack, install, update and remove packages without
building a new server image. Activation of a catalog change is at server
startup. The operator approves the exact checksum. A change in requested
authority also requires a space manager to enable that package in the space.
The catalog persists a bounded copy of the approved package and seeds shipped
packages on the first start. Workers use the same per-space broker and sandbox
for installed packages. Native Notes and Threads still have host bindings.

The guide explains, scaffolds and checks a manifest and can publish its
reference and walkthrough as a Markdown item in the current space. Its
packaged skill follows the Agent Skills layout. Installed-skill discovery
remains separate.

Fixture timings from `calternal-perf-02-backup01` under
`/usr/local/bin/perf-lock.sh` use the generated demo bundled on dev-02.
Cold starts measure process launch through the first result. Warm samples use
a single process and immediate fixture host responses.

## Part B

The owner selected stateful generated views. The [interface proposal](../plugin-interface-proposal.md)
describes the protected foundation, both layout models, sealed web frames,
Swift rendering, extension gaps, same-privilege checks and the three-author
acceptance run. The server prototype lists available fixed-slot contributions
through `plugins.list`. It checks package activation and the caller's
operation capability. Sealed renderer declarations are validated metadata
pending isolation and asset delivery. The headless view benchmark measures
worker-to-host patch transport, with the 60-row viewport and streaming append
at 0.118 ms and 0.070 ms p95 respectively.

| 2 | Uses existing crates and `rusqlite`. Package storage depends on the plugin host and filesystem primitives. |
| 3 | Package catalog reads and writes run at startup or on the operator CLI. Space activation reads use the existing per-space store and indexed control record. |
| 4 | Package reads, schema compilation, subprocess starts and durable catalog writes are outside the async request executor. |
| 5 | Warm SDK invocations use one JSON decode per inbound frame and one serialization per outbound frame. ## Unfinished and review questions

- The live install and reload plan was approved in #50. A bounded worker
  handshake commits activation. The topology measurement precedes implementation.
- The stateful patch/event runtime, plugin-owned slots, scoped reactive values,
  readiness and diagnostics, durable waits, and the Notes and Threads service
  ports follow the agreed sequence. The canvas trial precedes shell rendering.
- The renamed-package parity cases and source check depend on removing native
  host identity branches and provider defaults. The proposal inventories
  those exceptions and names the public contracts needed to remove them.
- Diagnostics include JSON parse lines and columns. Semantic manifest errors
  currently report the validation category. The Luna acceptance run is
  pending the live loop and the APIs exercised by its three requests.

## Simplification opportunities

Build the catalog with already validated schemas and reuse unchanged package
revisions on publication. Move provider selection and native engine dispatch
to public service slots. Use the same manifest documentation and readiness
protocol for the CLI, guide and future plugin management clients.
