# Small plugin microVM

Issue [#88](https://git.kayg.org/kayg/calternal-ai/issues/88). This lane
covers the small plugin runtime. The agent and heavy plugin runtimes have
separate placements.

## Proposed revisions

1. **Enrolled placement and vsock.** Reserve an eligible pool placement
   after admission. Its control plane carries the verified worker source
   and a small-VM selector. A capacity heartbeat advertises whether the
   operator configured that wall. The machine terminates the enrolled
   carrier and relays only the existing child protocol through its
   authenticated vsock exec connection. The guest starts the package
   using the rootless, read-only worker profile. Machine credentials and
   invocation tickets remain outside the guest. The guest has two vCPUs,
   256 MiB of memory, a bounded scratch disk and no network adapter.
2. **Cold boot entropy and readiness.** Take independent host randomness
   for the guest control capability and kernel reseed material. Carry
   them on the existing read-only boot drive. The guest init establishes
   kernel randomness before starting its trusted control agent. The
   machine requires the small-profile readiness response before starting
   a package. Node starts as a fresh process after that response.
3. **Snapshot and restore boundary.** Drain the carrier before sleep
   so the snapshot carries zero package processes, tickets, or child
   pipes. Reinitialize packages from verified source after restoring the
   guest and refreshing kernel entropy. Record the actual snapshot and
   readiness format when the restore fixture proves those steps.

The warm broker still uses two SQLite queries, with one additional query
for an installation session, and zero storage flushes. Existing channel
flow control bounds the child pipe. Cold placement uses the worker lease's
existing two durable commits and checks KVM and image integrity at role
startup. The test config uses a disposable guest image with Node 24 and
the existing rootless worker seccomp profile. Timings from dev-01 serve
only as functional deadline assertions.

## Development verification

The live KVM fixture runs the enrolled runner and the guest worker image.
It returns four maximum-size item heads over one carrier and confirms the
Firecracker process exits after one explicit fence. The fixture uses
Firecracker 1.16.1 and the locked guest kernel. The measurement lane's
`reseed.c` supplied the kernel reseed sequence. The product reuses the
existing guest build, Node worker seccomp policy and vsock exec transport.

Use the machine's Auto backend with `--space-vm-config PATH`. Put the
digest-pinned guest image in the existing immutable image layout, with a
Node worker rootfs. Configure 256 MiB, two vCPUs, zero warm guests and omit
network policy. The role verifies the image and opens KVM at initialization.

## Simplification opportunities

Keep the guest package transport on the existing authenticated vsock exec
pipe. Reuse the same VMM ownership, control and teardown primitives for
each placement role while keeping their capacity and guest images distinct.
