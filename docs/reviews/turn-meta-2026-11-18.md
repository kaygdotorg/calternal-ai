# Per-turn provider selection and history

[Forgejo #46](https://git.kayg.org/kayg/calternal-ai/issues/46) tracks this lane.
[Threads](../threads.md#models-phases-and-turn-history) documents the client
contract and [provider protocol](../provider-protocol.md) documents the adapter.

The picker reads the model catalog from the authorized space's enabled provider
manifests. Send pins its selected model and validates its explicit reasoning
level before saving the prompt. The existing job stream publishes work phases
and redacted reasoning deltas. The shared Markdown records each attempt's
chosen provider, model, effort, thread-scoped personal placement and terminal timing. The
full read and delta read deliver the same bytes. Pool placement stays anonymous.
The fixture uses the real adapter and a scripted stand-in for the official CLI.

## Decisions still open

- Account-specific availability could use the current installed manifest alone,
  or combine it with cached per-machine or per-account provider reports. The
  latter would represent gateway and entitlement differences, at the cost of
  probe scheduling, cache invalidation and an explicit stale or unknown state.
- Pinned defaults give the saved model a stable identity. A rolling alias
  supports more CLI versions and backends automatically, but would need a
  reliable resolved-model field and may change behavior at provider release time.
  The current branch pins the documented Anthropic CLI default for Sonnet 5.5.
- Explicit effort is observable as a request. Effective effort can differ
  under organization caps. Recording it would require a provider-reported
  effective value or a separate account configuration read.
- A cancelled or abruptly interrupted attempt can keep only its prior text
  checkpoint. Saving a final duration during stop would require extending the
  fenced stop path to update the file or storing timing snapshots at earlier
  checkpoints. The first adds a stop-time durable write and races to fence.
  The second preserves elapsed-to-checkpoint time and adds repeated markers.
- Personal placement uses a thread-scoped reference and pool placement stays
  anonymous. Exposing the raw UUID would change the existing machine privacy
  guarantee in shared spaces. Owner-only raw history would require a private
  side record with explicit retention and an owner-authorized read.
- The current Claude stream exposes thinking text without a distinct
  credential-safe summary field. An explicit provider summary format would
  need a contract for when it may be stored. Summarizing text in the host would
  require processing additional data and defining a separate privacy policy.

## Simplification opportunities

Catalog and readiness already share the space activation query. A single
typed snapshot for indexed activation could also avoid cloning control values
in both callers. The existing use of byte insertions makes a terminal comment
fit without a new delta operation. Any future structured message response can
derive from the same marker grammar instead of introducing independent history.
