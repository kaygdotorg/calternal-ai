# Threads lane, 2026-11-17

Issue: [#28](https://git.kayg.org/kayg/calternal-ai/issues/28). Branch:
`lane/threads`. Thread: `thr_z5xshybyaz`. This lane implements backend build step 2;
it does not change UI, worker/container launch, Notes package names or production.

## Result

The orchestrator manifest owns `threads` and declares create/list/get/send/stop/
archive/delete once, including capabilities, risk and targets. The host reuses
content Markdown placement, revisions, receipts, journal and guarded Trash moves;
send admits an existing `agent.turn` with the thread UUID. Human messages and
bounded scrubbed provider checkpoints share one readable `AI/Chats/<title>.md`.
Checkpoint updates preserve one stable message ID per agent response. Stop acknowledges lease release and its receipt identifies exactly the canceled job. Deletion
removes retained permission modes for every account using the shared thread.
Archived children remain discoverable by their parent. The CLI supplies all seven
operations with common human/JSON output and goldens.

[Thread format and operation counts](../threads.md) documents the recovery intent,
lock order, read/commit counts and bounds. This is a disposable development preview,
not a claim of complete file-only recovery or long-thread performance.

## Owner decisions applied (2026-11-18)

A mode supplied on `agent.run` or `threads.send` now applies directly in either
direction, persists for that account/thread and replaces the credential without
an additional passkey check. The nine possible mode transitions have independent
protected-store/token assertions; the saved-thread provider fixture exercises the
HTTP send path. Omitted modes use the sender's protected mode, never another
member's last shared-file choice. Agent credentials cannot choose a mode.

Standing space instructions are read only from `AI/AGENTS.md`; the former name
is deliberately ignored. One shared host path constant generates the SDK
constant. Manifest validation and content allocation/materialization reject the
reserved path, including portable-case variants and attempts to use the file as
a directory. The conformance fixture checks Editor writes and foreign-space
hiding. No Manager write API is invented: the current preview file remains
operator-provisioned pending the narrow settings-operation versus protected-file
writer contract in morning-decisions.md.

The requested consumed-on-use and thread-lifetime approvals need a separate lane:
atomic consumption/replay and protected persistent grants are outside this
storage delivery. Current grants still last one turn; always-in-space is later.
The coordinator has this handoff.

## Unfinished work and questions

- Approval lifetimes "once" and "this thread" are explicitly handed to a separate
  protected-grant lane. The requested Manager-only instructions writer needs its
  operation contract settled; generic kind writes remain prohibited.

- Active-turn steering is not wired: the provider protocol supports it, but machine
  exec input is delivered once. The existing turn engine refuses a concurrent or
  interrupted send. Incremental input is required to meet the accepted behavior;
  this lane does not silently choose replacement/cancellation semantics.
- Cross-turn provider-session continuation/history handoff is not wired by the
  manual turn engine. Each send currently admits a fresh job; this lane does not
  invent a transcript truncation or provider-handoff policy.
- Large-output companion storage and tail/block indexing remain unimplemented.
  The accepted one-file layout stands; no splitting policy is introduced.
- List filters currently operate within the first 1,000 content metadata rows;
  there is no cursor or arbitrary-depth child index yet.
- The current dispatch is a manifest-backed native engine, following the existing
  native Notes adapter. A TypeScript orchestrator worker/public engine bridge is
  still required for full ordinary-plugin parity; no plugin sandbox execution
  claim is made for this native engine.
- An addressable standard thread collection is not declared yet: the current
  foundation writes standard collections as JSON, while the accepted format is
  the inherited Markdown Views file. The lane does not enable another JSON
  userdata file to work around that foundation gap.
- The long-output artifact shape is recorded with options/costs in
  [morning decisions](../morning-decisions.md). No other product decision is made.
- The pin owner must refresh the affected bundle digest and rerun dependent gates
  before integration; failed gate results block merging this branch into dev.

## Simplification opportunities

- Pass the already loaded content head through outbox publication and placement
  instead of allocating the whole thread again at each internal durability step.
- Give native product engines the same compiled input/output validator interface
  as workers, removing duplicated validation adapters over time.
- Replace the remaining manual receipt adapter once all controls share item-aware
  admission; retain one receipt namespace and one per-space lifecycle fence.
