## Morning security decisions

- **Revocation ordering.** Signing out while a plugin is running raises the question of whether an already-started effect may commit. An admission-only check permits work already in flight and is cheaper. Fencing publication prevents a later commit from the revoked installation and requires coordination with auth. Use the stricter fence for persistent effects and stop passive socket delivery as soon as authority is lost.
- **Worker and live resource ceilings.** Concurrent workers or live windows multiply node memory, result size and refresh work even when every frame is valid. Operator-adjustable quotas accommodate larger deployments but need enforcement and defaults. Until those are defined and tested, keep coded execution limited to trusted development installations and require hard concurrency, output and memory ceilings before expanding access.
- **Torn append repair.** An unverified tail can represent either an interrupted host append or an outside edit. Automatic truncation without durable intent risks losing the outside edit. Preserve unverified bytes until reconciliation is possible. If an additional durable marker or staged publication is needed, take the extra flush and measure it separately.
- **Viewer state across plugin boundaries.** A plugin with a content grant may need a state-dependent computed field, such as an unread count. Making those results visible buys composability but can disclose a person's state through derived values. Keep foreign-kind raw state and state-derived results out of reaction inputs until an explicit disclosure rule is approved.

## Simplification opportunities

- Use one typed authorization and normalization step for the HTTP call, coded
  operations, callbacks and live evaluation. Apply the same typed format save
  checks across normal writes and previews.
- Use one canonical operation identifier and generate the SDK and wire
  vocabularies from the same declarations.
- Give live subscriptions a bounded metadata or record-suffix path. A snapshot
  can remain the explicit recovery response when its anchor is gone.
- Let receipt lookup distinguish replay from new commit directly. Observation
  delivery can then follow a durable intent instead of inferring a change from
  an old result and the current index.
