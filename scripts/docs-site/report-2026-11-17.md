## Unfinished work and questions

- 24 of 42 command pages lack exact human and JSON golden output fixtures in the
  source tree. They include invocation patterns and registered shapes where
  available and explicitly label missing recorded examples. No output was invented.
- `operations.json` currently exports only id, description, mutates and schemas.
  It does not declare capability or risk. Pages state the capability metadata is
  absent and leave authority with host policy. A future exporter can expose that
  metadata once the backend lane settles its single source; this lane does not
  parse Rust policy source with a fragile duplicate parser.
- Machine and secrets READMEs disagree with later decisions. The relevant admin
  pages label the conflicts. Their source owners must reconcile implementation
  and reference text; this lane cannot modify crates.
- There is no complete verified backup/restore runbook in the allowed source
  material. Recovery documentation identifies that limit rather than inventing
  operational commands.
- Rust Markdown is converted HTML; Rust pages are linked from the LLM corpus,
  rather than included in its full text. A stable rustdoc JSON export could
  improve this later without a nightly toolchain.
- No unresolved framework, deployment or product design decision was made here.
  Source gaps are recorded on #21. The UI lane can theme Starlight later.

## Simplification opportunities

Unify the existing reference-doc and site dependency sets when their owning lane
can update both. Add missing CLI goldens to make every command example exact.
Expose capability/risk metadata in the canonical catalogue instead of teaching a
documentation generator another policy parser. Reconcile stale crate READMEs so
the site can remove its source-conflict notices.
